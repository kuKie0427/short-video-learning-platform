## 5. 质量结论与遗留风险

**结论**：出口准则全部满足，版本达到课设交付质量标准，可提请答辩/发布。

**遗留风险（明示）**：

1. SenseVoice 模型内部精度未验证（黑盒边界，集成契约已测）
2. 短信通道真实到达率未测（逻辑路径已测）
3. Kafka 未接入，接入后需补消息链路测试
4. 性能基线含本机微基准与容器化整链路两层：本机单进程·无缓存形态（2026-09-04 负载阶梯，perf/BASELINE.md）过线天花板 ≈90 并发（P95 410ms）、吞吐天花板 ≈73 RPS，200 并发饱和（P95 2.7s、0 失败优雅降级，瓶颈为混合推荐链路）；容器化整链路（Docker 全栈+网关+Redis，2026-09-05，perf/BASELINE.md 网关专节）200 并发 P95 47ms/吞吐 147.5 RPS/0 失败全过门禁（200ms/1%）——生产形态容量已实测，非推测
5. **边界校验规则同类不一致（已登记、未修）**：同为关键词检索，`/api/feed/search`（feed.py:737）与 `/api/search/suggest`（search.py:20）声明 `q ∈ [1,100]`，而 `/api/search/videos`（search.py:78）的 `q` 可选且无长度上限——实测 `q=` 空串与 `q=<101 字符>` 均返回 200。同类情：`/auth/send-code` 的 `phone` 只有下限（`len < 10` 拦，auth.py:43），无上限（30 位仍发码，用例 `long-phone` 已把这一现状行为锁定为 200）。已按实测修正手工用例 R05 预期并在《测试设计文档》标注端点差异；建议后续统一契约并补参数化用例（改动会打破现行 315 例口径，故本次未动）
6. 手工冒烟尚有视觉/兼容/手感类条目未留痕（V1-V8、B01-B04、S05 等），需真机/多浏览器人工判定

## 7. 复盘（经验与教训）

1. 断言标准三位一体（状态码+响应体+数据库最终态）——BUG-004 的直接教训
2. 同源缺陷要同源修复+同源回归（LIKE 转义在 search/feed 两处）
3. E2E 能发现纯接口测试发现不了的部署级问题（硬编码路径）
4. 探索性测试是自动化用例的发现源头，不是被淘汰的旧做法
5. **文档里的每条命令都是用例**——照抄 README 验证命令即现 404（BUG-017）：可执行命令必须跑一遍再入库
6. **失败要定界到层再下结论**——同一条 E2E 失败，上次根因是 `UPLOAD_BASE_DIR` 缺失，这次是网关上游 IP 陈旧；现象相同、归因不同，只有比对容器内直连与网关日志才能分清是产品、配置还是文档问题
