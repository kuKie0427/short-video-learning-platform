【BUG-016 定界证据】网关上游 IP 陈旧 → /api/split/* 全 502
$ curl -o /dev/null -w "%{http_code}" http://localhost/api/split/tasks        -> 502
$ docker exec api_gateway wget -qO- http://split_service:8004/health          -> {"status":"healthy","service":"split"}
$ docker logs api_gateway | grep error
  connect() failed (111: Connection refused) while connecting to upstream,
  request: "POST /api/split/direct-split", upstream: "http://172.19.0.10:8004/api/split/direct-split"
$ docker exec api_gateway nginx -s reload
$ curl … http://localhost/api/split/tasks                                     -> 403 {"detail":"Not authenticated"}
$ curl … http://localhost/api/split/tasks -H "Authorization: Bearer <DEV_UUID>" -> 200（上游已恢复连通；此前为 502）
→ 结论：不是产品功能缺陷，是 nginx 启动期一次性解析 upstream 并缓存容器 IP；容器重建后 IP 变更未刷新
→ E2E 首跑 5/6 失败即此因；reload 后 6/6 全绿（19.6s）
