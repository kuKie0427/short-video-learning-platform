# 测试计划（Test Plan）

> 项目：教育短视频学习平台 ｜ 编写：测试负责人
> 配套文档：测试设计文档（策略与用例方法）· 手工测试用例-正式版（执行条目）· 缺陷台账（缺陷记录）

---

## 1. 项目概述与测试目标

被测对象：7 个 FastAPI 微服务（auth/content/upload/split/course/search/notification）、56 个 REST 接口、前端 React 18 SPA。核心业务风险集中在**音视频切分链路的数据一致性**与**推荐/互动逻辑的正确性**。

测试目标（按优先级）：
1. 核心业务链路（登录、上传、切分、推荐、搜索）功能正确，数据落盘一致
2. 接口契约稳定：鉴权边界、参数校验、错误语义（4xx/5xx 分界）
3. 回归可快速重复：全量回归稳定在 20 秒量级（实测 18–22s），可进 CI 门禁
4. 核心读链路有性能基线，回归可对比

## 2. 测试范围（含明确不测项）

**测**：7 服务 56 接口的功能/边界/安全/幂等；前端登录与路由守卫组件行为；核心链路 E2E 冒烟；4 条核心读接口性能；手动冒烟/探索/视觉 29+ 条。

**不测（明示）**：
- Kafka——部署于 compose 但业务未接入，无可测行为
- S3 存储——可选项，当前本地磁盘方案生效
- SenseVoice ASR 模型内部精度——只测集成行为（输入音频→转写输出契约）
- 第三方短信通道真实到达率——mock/内存降级验证逻辑
- 前端除登录/守卫外的组件单元细节——由 E2E 冒烟兜底

> 口述要点：范围里"不测什么"与"测什么"同等重要——每一条不测项都有理由（未接入/可选项/外部黑盒），这是测试计划的负责人级判断。

## 3. 测试策略与分层

| 层 | 数量 | 归属 | 职责 |
|---|---|---|---|
| 单元测试 | 151 | 开发（测试定门禁验收） | 推荐算法/工具函数/AI 降级纯逻辑 |
| 接口集成测试 | 164 | 测试负责人 | 真库副作用/鉴权边界/幂等/安全 |
| 前端组件 | 10 | 测试 | 登录/守卫/上下文 |
| E2E 冒烟 | 6 | 测试 | 跨服务真实链路存在性 |
| 手工 | 56 条编号用例（另 29 条快查清单） | 测试 | 视觉/探索/发布冒烟 |

质量门禁：全量绿 + 总覆盖率 ≥ 70%（实测 75.4%）+ 5 个智能切分核心模块分级底线（10/15/45/60/60）+ E2E 冒烟绿。

## 4. 测试环境

- 本地：Docker Compose（PG15 + Redis + 7 服务 + nginx 网关）+ 前端 vite dev
- CI：GitHub Actions，3 job（backend / frontend / e2e），PG 服务容器
- 测试数据：faker 生成 uuid/手机号，每用例建删表完全隔离，可重复执行
- 外部依赖锁定：Redis 锁内存路径、celery send_task patch、GLM Key 未配置走降级

## 5. 进入 / 出口准则

**进入**：冒烟链路可通（登录→上传→切分→推荐）；接口文档冻结；开发自测通过提测。
**出口（全部满足才可"测完"）**：
1. 计划内用例执行率 100%，无未执行项
2. 致命/严重级缺陷全部关闭并回归通过（本项目：严重 7 条全闭环）
3. 一般级缺陷关闭或挂起有书面理由
4. 全量自动化回归绿 + 覆盖率门禁绿
5. 性能基线无超标项（P95 < 500ms、失败率 < 1%）
6. 测试总结报告出具并评审

> 口述要点：被问"什么时候可以停止测试"→ 出口准则逐条背；被问"时间不够怎么办"→ 按风险排序砍低优先级用例，不砍冒烟与严重级回归。

| GLM Key 依赖外部服务可用性 | 切分链路不可测 | 无 Key 降级路径专项用例，行为可预期 |
