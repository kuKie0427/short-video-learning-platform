# 测试运行指南

本文是测试的**环境与执行手册**：装什么、怎么连数据库、怎么跑、门禁在哪、报错怎么办。
策略与用例体系见《测试设计文档.md》，套件就近速查见 [tests/README.md](../tests/README.md)。

## 📊 套件概况

| 指标 | 值 |
| --- | --- |
| 用例规模 | 315 条 = API 集成 164（17 文件）+ 单元 151（15 文件），其中 42 条为参数化矩阵 |
| 测试库 | PostgreSQL，库名 `short_video_platform_test`（逐用例建表/删表隔离） |
| Redis | **无需启动**（conftest autouse 把 `get_redis` 锁定为内存降级路径） |
| Celery | **无需启动**（split 用例 patch 掉 `send_task`，不连 broker） |
| ffmpeg | **必须在 PATH**（`RealVideoSplitService` 构造时 `shutil.which("ffmpeg")` 校验） |
| 总量门禁 | `--cov-fail-under=70`（pytest.ini 内置，`pytest tests/ -q` 即生效） |
| 全量耗时 | 纯用例 ~18s（实测 17.7–19.5s）、含覆盖率报告 ~22s（2026-09-09 复测）；轻负载历史实测 ~13s。秒级，无需并行 |

## 前置要求

1. **Python 3.11+**（项目用 uv 管理 `backend/.venv`）
2. **PostgreSQL** 运行中。本地用 `backend/docker-compose.yml` 的 `postgres:14` 服务（凭证 `app_user`/`app_password_2025`，端口 5432）
3. **ffmpeg** 已安装（macOS: `brew install ffmpeg`；CI ubuntu runner 不预装，workflow 已显式 `apt-get install`）
4. **测试依赖**已在 `backend/requirements.txt`（pytest 7.4.3、pytest-asyncio 0.21.1、pytest-cov 4.1.0、httpx、faker、freezegun、psycopg[binary] 3.x）

## 安装依赖

```bash
cd backend

# 方法1：uv（推荐，与项目 .venv 现状一致）
uv pip install -r requirements.txt

# 方法2：pip（激活虚拟环境后）
pip install -r requirements.txt

# 方法3：不激活环境，直接指定虚拟环境解释器
.venv/bin/python -m pip install -r requirements.txt
```

## 准备测试数据库

`tests/conftest.py` 导入时会自动探测并创建测试库（psycopg 管理连接，`CREATE DATABASE short_video_platform_test`），权限不足时打印提示。手动准备与诊断：

```bash
cd backend

docker-compose up -d postgres                 # 1. 启动 PostgreSQL
.venv/bin/python scripts/create_test_db.py    # 2. 创建测试数据库（自动创建失败的兜底）
.venv/bin/python scripts/test_connection.py   # 3. 连接诊断
```

**连接串规则**（`tests/conftest.py`）：

- 默认拼装 `postgresql+psycopg://{DB_USER}:{DB_PASSWORD}@{host}:{DB_PORT}/short_video_platform_test`
- conftest 强制 `DB_HOST=127.0.0.1`（规避 localhost 解析到 IPv6）、`DB_NAME=short_video_platform_test`
- 环境变量优先：`TEST_DATABASE_URL` 整串覆盖，`TEST_DB_HOST` 单独换主机
- CI 以 `DB_USER=postgres`/`DB_PASSWORD=postgres` 环境变量接入 postgres:15 服务容器

## 运行测试

### 全量（与 CI 一致的推荐命令）

```bash
cd backend
pytest tests/ -q
# pytest.ini addopts 已内置覆盖率与 70% 门禁，未达门禁返回码非 0
```

### 按目录 / 文件 / 类 / 方法

```bash
pytest tests/unit/                                            # 仅单元测试
pytest tests/api/                                             # 仅 API 集成测试
pytest tests/api/test_auth.py                                 # 单文件
pytest tests/api/test_auth.py::TestLogin                      # 单类
pytest tests/api/test_auth.py::TestLogin::test_login_success  # 单方法
```

### 按标记（子集过滤）

pytest.ini 注册了 `unit` / `api` / `integration` / `slow` 四个标记（`--strict-markers` 开启）。315 条中 290 条带标记、25 条未带。**按标记跑是子集过滤，不是完整分层**，分层执行请用目录路径。

```bash
pytest -m "not slow"
pytest -m api
```

### 调试输出

```bash
pytest -v       # 逐用例列名
pytest -vv -s   # 最详细 + 放行 print
```

## 覆盖率报告

```bash
cd backend
pytest tests/ -q          # addopts 已含 --cov=common --cov=services --cov-report=html
open htmlcov/index.html   # macOS；Linux 用 xdg-open，Windows 用 start
```

### 覆盖率门禁

- **总量门禁**：`--cov-fail-under=70`（pytest.ini 内置；全量实测 75.4%，逐次小幅漂移）
- **分级门禁**：核心业务模块独立底线，防被总量平均数掩盖。需先跑过 pytest 生成 `.coverage` 数据：

```bash
.venv/bin/python scripts/check_coverage_gates.py   # 返回码非 0 即失败
```

| 模块（backend 相对路径） | 底线 |
| --- | --- |
| services/split/app/services/smart_split/keyframe_extractor.py | 10% |
| services/split/app/services/video_splitter.py | 15% |
| services/split/app/services/smart_split_service.py | 45% |
| services/split/app/services/smart_split/knowledge_analyzer.py | 60% |

## 常见问题

### 1. ModuleNotFoundError: No module named 'pytest'

未装测试依赖或未进虚拟环境：`cd backend && .venv/bin/python -m pip install -r requirements.txt`，或直接 `.venv/bin/python -m pytest tests/ -q`。

### 2. ModuleNotFoundError: No module named 'common'

必须在 **backend 目录下**运行（conftest 会把 backend 根目录注入 `sys.path`）。自检：`python -c "from common.models import User; print('OK')"`。

### 3. 数据库连接失败 / "Operation not permitted"

- 确认 PostgreSQL 在跑：`docker-compose ps postgres`，端口 5432 已映射
- conftest 已强制 `127.0.0.1`（规避 IPv6）；容器网络场景核对 `DB_HOST` 环境变量
- macOS 偶发容器权限问题：`docker-compose restart postgres`
- 兜底手动建库：`docker-compose exec postgres psql -U app_user -d postgres -c 'CREATE DATABASE short_video_platform_test;'`

### 4. split 用例构造报错（ffmpeg not found）

PATH 里没有 ffmpeg：安装后重跑（`ffmpeg -version` 自检）。CI 已在 workflow 中显式安装。

### 5. Redis 连接错误

不需要处理，测试与 Redis 是否可用无关：autouse fixture 把三个 `get_redis` 入口 patch 为返回 None，验证码等状态走内存 store 且逐用例清空。若要手工验证 Redis 真实链路：`docker-compose up -d redis` 后 `docker exec -it short_video_redis redis-cli ping`。

## 编写新测试

1. 复用 conftest 夹具：`db`、`client` 及各服务 client、`test_user`/`test_user2`、`test_video`、`test_course`、`auth_headers`；无效凭证在测试内构造（参考 `test_security.py` 的 `_expired_token()`/`_forge_token()`）
2. 遵循 AAA（Arrange-Act-Assert），断言三件套：状态码 + 响应体 + 数据库最终态
3. 动态数据（手机号等）用 faker/uuid 生成，保证可重复执行；用例间不共享数据
4. 同接口多组输入用 `@pytest.mark.parametrize`，`id=` 起可读名字；依赖 fixture 动态值的参数用 lambda 惰性解析，保持参数表静态可收集
5. 发现缺陷先写复现用例（必须失败），修复后转普通用例长期驻留（机制见《测试设计文档.md》§4）
6. 全量在 20 秒量级内不必引入并行；用例规模显著增长再考虑 pytest-xdist
