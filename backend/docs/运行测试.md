## 常见问题

### 1. ModuleNotFoundError: No module named 'pytest'

**解决方案**：安装pytest
```bash
pip install pytest
```

### 2. Redis连接错误

**说明**：测试已实现Redis fallback机制，当Redis不可用时自动使用内存存储。

**如果需要测试Redis功能**：
```bash
# 启动Redis
docker-compose up -d redis

# 验证Redis连接
docker exec -it short_video_redis redis-cli ping
```

### 3. 数据库连接错误

**说明**：测试使用独立的测试数据库（`short_video_platform_test`）。

**解决方案**：
```bash
# 1. 启动PostgreSQL
docker-compose up -d postgres

# 2. 创建测试数据库
python scripts/create_test_db.py

# 3. 测试连接
python scripts/test_connection.py

# 4. 如果仍有问题，检查配置
docker exec -it short_video_postgres psql -U app_user -l
```

**注意事项**：
- 测试使用 `127.0.0.1` 而不是 `localhost`（避免IPv6问题）
- 每个测试函数使用独立的数据库会话
- 测试后自动清理数据

### 4. 导入错误

**说明**：测试代码现在使用`common`模块，确保路径配置正确。

**解决方案**：
```bash
# 确保在backend目录下运行
cd backend

# 检查Python路径
python -c "import sys; print(sys.path)"

# 检查common模块是否可以导入
python -c "from common.models import User; print('OK')"

# 如果导入失败，检查backend目录结构
ls -la backend/common/
```

## 测试最佳实践

### 编写新测试
1. 使用 `conftest.py` 中的fixtures（`db`, `client`, `auth_headers`等）
2. 遵循AAA模式（Arrange-Act-Assert）
3. 使用有意义的测试名称
4. 测试边界条件和错误情况
5. 同接口多组参数的用例优先用 `@pytest.mark.parametrize`（参数表静态可收集，`id=` 命名可读）

### 测试数据管理
- 用 conftest 的 fixtures（`test_user`/`test_video`/`test_course`）构造数据，每个测试独立数据库会话
- 动态数据（如新用户手机号）用 `uuid` 生成，保证用例可重复执行
- 避免测试之间的数据依赖

### 性能优化
- 当前全量 ~13s，无需并行；若未来用例增长，可用 `pytest-xdist`
- 避免真实外部依赖（Redis 已锁定内存路径、celery 已 patch）
- 合理使用 `scope` 参数（function/class/module/session）

## 覆盖率门禁

- **总量门禁**：`--cov-fail-under=70`（pytest.ini addopts 内置，CI 直接 `pytest tests/ -q` 即生效）
- **分级门禁**：核心业务模块独立底线（`scripts/check_coverage_gates.py`，CI 已接入）：

```bash
../.venv/bin/python scripts/check_coverage_gates.py   # 返回码非 0 即失败
```
