# 项目启动指南

本指南覆盖 Docker Compose 与本地开发两种启动方式。数据库相关专项说明见[数据库本地部署](数据库本地部署.md)，快速上手见[快速启动](../QUICK_START.md)。

## 服务与端口

| 服务 | 端口 | 说明 |
|------|------|------|
| Auth | 8001 | 认证授权 |
| Content | 8002 | 内容推荐、互动、关注 |
| Upload | 8003 | 视频上传（分片、合并） |
| Split | 8004 | 视频拆分（智能/等长） |
| Course | 8005 | 课程管理、学习进度 |
| Search | 8006 | 视频搜索 |
| Notification | 8007 | 消息通知 |
| API 网关 | 80 | Nginx 统一入口，转发 `/api/*`，静态服务 `/uploads/` 与 `/smart_split_output/` |

## 前置条件

### Docker 方式

- Docker 与 Docker Compose

### 本地开发方式

- Python 3.11+（Dockerfile 基于 `python:3.11-slim`）
- PostgreSQL 14（compose 使用 `postgres:14` 镜像）
- Redis 7（compose 使用 `redis:7-alpine` 镜像）
- Kafka 可省：服务代码不在启动时连接 Kafka，本地跑单个服务不需要；compose 全量启动包含 Kafka 与 Zookeeper

## 方式一：Docker Compose 启动

### 1. 启动

```bash
cd backend

# 容器名冲突时执行清理，正常可跳过
./scripts/cleanup_docker.sh

docker-compose up -d
```

各服务的连接参数（DATABASE_URL、REDIS_HOST、REDIS_PORT 等）内联在 `docker-compose.yml` 中。`.env` 只参与三处默认值插值：

- `JWT_SECRET_KEY`，默认 `your-secret-key-change-in-production`
- `ENVIRONMENT`，默认 `development`
- `GLM_API_KEY`，默认空

### 2. 查看状态与日志

```bash
docker-compose ps
docker-compose logs -f [service]
docker-compose logs -f auth-service
docker-compose logs -f content-service
```

### 3. 验证

```bash
curl http://localhost:8001/health  # Auth
curl http://localhost:8002/health  # Content
curl http://localhost:8003/health  # Upload
curl http://localhost:8004/health  # Split
curl http://localhost:8005/health  # Course
curl http://localhost:8006/health  # Search
curl http://localhost:8007/health  # Notification
curl http://localhost/health       # 网关

open http://localhost:8001/docs    # Auth 的 API 文档
open http://localhost:8002/docs    # Content 的 API 文档
```

也可直接运行 `./scripts/diagnose.sh` 逐项诊断。

### 数据与存储

- 上传文件写入宿主机 `backend/data/`（compose 将 `./data` 挂载为容器内 `/app/data`，上传目录为 `/app/data/uploads`）
- 切分产物位于命名卷 `split-output`
- 默认本地磁盘存储（`UPLOAD_BASE_DIR=/app/data/uploads`）。S3/MinIO 是可选的部署形态，`docker-compose.yml` 未内置 MinIO 服务，使用 S3 模式需自备对象存储服务

### Split 服务说明

- 智能拆分依赖 `GLM_API_KEY`；未配置时自动降级为等长切分
- compose 将仓库根目录的 `SenseVoiceSmall` 挂载进容器（只读），供语音识别使用
- `split-worker` 为 Celery worker，启动命令见 `docker-compose.yml`，broker 与 backend 使用 Redis

### 数据库初始化

每个服务启动时调用 `init_db()`，通过 SQLAlchemy `create_all` 自动建表，并写入一个演示用户（手机号 `13800138000`）。表结构与操作见[数据库本地部署](数据库本地部署.md)。

## 方式二：本地开发模式

### 1. 安装依赖

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

根目录 `requirements.txt` 覆盖所有服务的公共依赖（FastAPI、SQLAlchemy、psycopg、Redis、kafka-python、Celery、Alembic 等）。专属依赖按需安装：

```bash
pip install -r services/split/requirements.txt     # torch、funasr、zhipuai 等智能拆分依赖
pip install -r services/upload/requirements.txt    # boto3，仅 S3 存储模式需要
```

### 2. 配置环境变量

在 backend 根目录运行服务时，pydantic-settings 读取 `backend/.env`（`common/config/settings.py` 按当前工作目录查找 `.env`）。`env.example` 提供的是 Docker 内部主机名，本地开发需覆盖：

```bash
cp env.example .env
```

在 `.env` 中修改为：

```bash
DB_HOST=localhost
REDIS_HOST=localhost
```

也可以不建 `.env`，直接导出环境变量：

```bash
export DATABASE_URL=postgresql://app_user:app_password_2025@localhost:5432/short_video_platform
export REDIS_HOST=localhost
export KAFKA_BOOTSTRAP_SERVERS=localhost:9092
```

未配置时的默认值（`common/config/settings.py`）：`ENVIRONMENT=development`、`REDIS_HOST=localhost`、`KAFKA_BOOTSTRAP_SERVERS=localhost:9092`、`JWT_SECRET_KEY` 回退为 `your-secret-key-change-in-production`。生产环境必须显式设置 JWT 密钥，且 `CORS_ORIGINS` 不得为 `*`。

### 3. 启动基础设施

```bash
cd backend
docker-compose up -d postgres redis kafka
```

`zookeeper` 随 `kafka` 自动启动。本地模式跑单个服务时不依赖 Kafka 运行。

### 4. 启动服务

在 backend 根目录逐个启动，模块路径为 `services.<服务名>.app.main`：

```bash
python -m uvicorn services.auth.app.main:app --host 0.0.0.0 --port 8001 --reload
python -m uvicorn services.content.app.main:app --host 0.0.0.0 --port 8002 --reload
python -m uvicorn services.upload.app.main:app --host 0.0.0.0 --port 8003 --reload
python -m uvicorn services.split.app.main:app --host 0.0.0.0 --port 8004 --reload
python -m uvicorn services.course.app.main:app --host 0.0.0.0 --port 8005 --reload
python -m uvicorn services.search.app.main:app --host 0.0.0.0 --port 8006 --reload
python -m uvicorn services.notification.app.main:app --host 0.0.0.0 --port 8007 --reload
```

每个服务占用一个终端。若在 `services/<服务名>/` 目录下启动，需自行导出 `DATABASE_URL`、`REDIS_HOST` 等环境变量（该目录没有 `.env`）。

## 验证失败排查

`./scripts/diagnose.sh` 检查 Docker 版本、容器状态、PostgreSQL/Redis 健康、7 个服务的 `/health`、最近错误日志与端口占用。

详细排查步骤见[故障排查指南](故障排查指南.md)。

## 常用命令

### Docker Compose

```bash
docker-compose up -d            # 启动全部服务
docker-compose stop             # 停止（保留容器与数据）
docker-compose down             # 停止并删除容器
docker-compose down -v          # 同时删除数据卷
docker-compose restart          # 重启
docker-compose ps               # 状态
docker-compose logs -f [service]  # 日志
docker-compose up -d --build [service]  # 重建单个服务
```

### 数据库

进入 PostgreSQL、备份恢复、重置等命令见[数据库本地部署](数据库本地部署.md)。
