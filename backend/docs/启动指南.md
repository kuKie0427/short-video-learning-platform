# 项目启动指南

## 📋 前置条件

### 必需软件
- **Docker** 和 **Docker Compose**（推荐方式）
- 或 **Python 3.11+**（本地开发方式）
- **PostgreSQL 14+**（如果本地开发）
- **Redis 7+**（如果本地开发）
- **Kafka**（如果本地开发，可选）

### 检查环境
```bash
# 检查Docker
docker --version
docker-compose --version

# 检查Python（如果本地开发）
python3 --version
```

## 🚀 方式一：Docker Compose启动（推荐）

### 步骤1：清理旧容器（如果有冲突）

如果遇到容器名称冲突错误，先清理：

```bash
cd backend

# 使用清理脚本
./scripts/cleanup_docker.sh

# 或手动清理
docker-compose down
docker rm -f short_video_redis short_video_postgres short_video_zookeeper short_video_kafka 2>/dev/null || true
```

### 步骤2：启动所有服务

```bash
cd backend
docker-compose up -d
```

### 步骤3：查看服务状态

```bash
# 查看所有服务状态
docker-compose ps

# 查看服务日志
docker-compose logs -f

# 查看特定服务日志
docker-compose logs -f auth-service
docker-compose logs -f content-service
```

### 步骤4：验证服务

```bash
# 检查服务健康状态
curl http://localhost:8001/health  # Auth服务
curl http://localhost:8002/health  # Content服务
curl http://localhost:8003/health  # Upload服务
curl http://localhost:8004/health  # Split服务
curl http://localhost:8005/health  # Course服务
curl http://localhost:8006/health  # Search服务
curl http://localhost:8007/health  # Notification服务

# 访问API文档
open http://localhost:8001/docs  # Auth服务API文档
open http://localhost:8002/docs  # Content服务API文档
```

### 步骤5：运行数据库迁移（首次启动）

```bash
# 进入PostgreSQL容器
docker exec -it short_video_postgres psql -U app_user -d short_video_platform

# 或使用Alembic迁移（如果已配置）
cd backend
alembic upgrade head
```

## 🔧 方式二：本地开发模式

### 步骤1：安装依赖

```bash
cd backend

# 安装所有服务的依赖（每个服务有独立的requirements.txt）
# 或者安装common模块的依赖（如果有）
pip install -r services/auth/requirements.txt
pip install -r services/content/requirements.txt
# ... 其他服务类似

# 或者使用虚拟环境（推荐）
python -m venv venv
source venv/bin/activate  # macOS/Linux
# venv\Scripts\activate  # Windows
pip install -r services/auth/requirements.txt
```

### 步骤2：配置环境变量

创建`.env`文件：

```bash
# 数据库配置
DATABASE_URL=postgresql://app_user:app_password_2025@localhost:5432/short_video_platform
DB_HOST=localhost
DB_PORT=5432
DB_NAME=short_video_platform
DB_USER=app_user
DB_PASSWORD=app_password_2025

# Redis配置
REDIS_HOST=localhost
REDIS_PORT=6379

# Kafka配置（可选）
KAFKA_BOOTSTRAP_SERVERS=localhost:9092

# JWT配置
JWT_SECRET_KEY=your-secret-key-change-in-production

# 环境
ENVIRONMENT=development
```

### 步骤3：启动基础设施

```bash
# 启动PostgreSQL（如果使用Docker）
docker run -d \
  --name short_video_postgres \
  -e POSTGRES_DB=short_video_platform \
  -e POSTGRES_USER=app_user \
  -e POSTGRES_PASSWORD=app_password_2025 \
  -p 5432:5432 \
  postgres:14

# 启动Redis（如果使用Docker）
docker run -d \
  --name short_video_redis \
  -p 6379:6379 \
  redis:7-alpine
```

### 步骤4：启动服务

```bash
# 确保在backend目录下，以便正确导入common模块
cd backend

# Auth服务（终端1）
cd services/auth
python -m uvicorn app.main:app --host 0.0.0.0 --port 8001 --reload

# Content服务（终端2）
cd services/content
python -m uvicorn app.main:app --host 0.0.0.0 --port 8002 --reload

# Upload服务（终端3）
cd services/upload
python -m uvicorn app.main:app --host 0.0.0.0 --port 8003 --reload

# Split服务（终端4）
cd services/split
python -m uvicorn app.main:app --host 0.0.0.0 --port 8004 --reload

# Course服务（终端5）
cd services/course
python -m uvicorn app.main:app --host 0.0.0.0 --port 8005 --reload

# Search服务（终端6）
cd services/search
python -m uvicorn app.main:app --host 0.0.0.0 --port 8006 --reload

# Notification服务（终端7）
cd services/notification
python -m uvicorn app.main:app --host 0.0.0.0 --port 8007 --reload
```

**注意**：每个服务需要在独立的终端中启动，或者使用进程管理器（如`supervisord`或`pm2`）来管理多个服务。

## ❌ 验证失败排查

### 快速诊断

如果启动后验证失败，首先运行诊断脚本：

```bash
cd backend
./scripts/diagnose.sh
```

诊断脚本会自动检查：
- Docker和Docker Compose版本
- 容器状态
- 基础设施服务（PostgreSQL、Redis）
- 应用服务健康状态
- 最近错误日志
- 端口占用情况

### 手动排查步骤

#### 步骤1：检查服务状态
```bash
# 查看所有服务状态
docker-compose ps

# 应该看到所有服务状态为 "Up"
# 如果有服务状态为 "Exit" 或 "Restarting"，说明启动失败
```

#### 步骤2：查看错误日志
```bash
# 查看所有服务日志
docker-compose logs --tail=50

# 查看特定服务日志
docker-compose logs -f auth-service
docker-compose logs -f content-service

# 查找错误
docker-compose logs | grep -i error
docker-compose logs | grep -i exception
docker-compose logs | grep -i traceback
```

#### 步骤3：测试服务连接
```bash
# 测试健康检查端点
curl http://localhost:8001/health
curl http://localhost:8002/health

# 如果失败，查看详细错误
curl -v http://localhost:8001/health
```

#### 步骤4：检查基础设施
```bash
# 检查PostgreSQL
docker-compose exec postgres pg_isready -U app_user

# 检查Redis
docker-compose exec redis redis-cli ping

# 检查Kafka
docker-compose exec kafka kafka-broker-api-versions --bootstrap-server localhost:9092
```

### 常见验证失败原因

1. **服务未启动**：容器启动失败或立即退出
2. **数据库连接失败**：PostgreSQL未启动或连接配置错误
3. **Redis连接失败**：Redis未启动或连接配置错误
4. **代码错误**：导入错误、语法错误等
5. **端口冲突**：端口被其他进程占用

**详细排查请参考**：[故障排查指南](./故障排查指南.md)

## 🔍 常见问题

### 1. 容器名称冲突

**错误**：`Conflict. The container name "/short_video_redis" is already in use`

**解决**：
```bash
./scripts/cleanup_docker.sh
docker-compose up -d
```

### 2. 端口被占用

**错误**：`port is already allocated`

**解决**：
```bash
# 查看端口占用
lsof -i :8001

# 停止占用端口的进程或修改docker-compose.yml中的端口
```

### 3. 数据库连接失败

**检查**：
```bash
# 检查PostgreSQL是否运行
docker ps | grep postgres

# 检查连接
docker exec -it short_video_postgres psql -U app_user -d short_video_platform
```

### 4. 服务启动失败

**查看日志**：
```bash
# 查看所有服务日志
docker-compose logs

# 查看特定服务日志
docker-compose logs auth-service
docker-compose logs content-service
```

## 🛠️ 常用命令

### Docker Compose命令

```bash
# 启动所有服务
docker-compose up -d

# 停止所有服务
docker-compose stop

# 停止并删除容器
docker-compose down

# 重启服务
docker-compose restart

# 查看服务状态
docker-compose ps

# 查看日志
docker-compose logs -f [service_name]

# 重建服务
docker-compose up -d --build [service_name]
```

### 数据库操作

```bash
# 进入PostgreSQL
docker exec -it short_video_postgres psql -U app_user -d short_video_platform

# 运行迁移
cd backend
alembic upgrade head

# 创建新迁移
alembic revision --autogenerate -m "description"
```
