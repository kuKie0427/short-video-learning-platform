# 故障排查指南

## 🔍 验证失败常见原因

### 1. 服务未正常启动

#### 检查方法
```bash
# 查看所有服务状态
docker-compose ps

# 应该看到所有服务状态为 "Up"
```

#### 可能原因和解决方案

**原因1：容器启动失败**
```bash
# 查看服务日志
docker-compose logs auth-service
docker-compose logs content-service

# 常见错误：
# - ImportError: 模块导入失败
# - ConnectionError: 数据库连接失败
# - PortConflict: 端口被占用
```

**原因2：代码错误**
```bash
# 查看详细错误日志
docker-compose logs -f auth-service | grep -i error

# 检查Python语法错误
cd services/auth
python -m py_compile app/main.py
```

### 2. 数据库连接失败

#### 检查方法
```bash
# 检查PostgreSQL是否运行
docker ps | grep postgres

# 测试数据库连接
docker exec -it short_video_postgres psql -U app_user -d short_video_platform -c "SELECT 1;"
```

#### 常见错误

**错误1：数据库未启动**
```bash
# 解决方案：确保PostgreSQL容器运行
docker-compose up -d postgres

# 等待数据库就绪
docker-compose logs postgres | grep "database system is ready"
```

**错误2：连接字符串错误**
```bash
# 检查环境变量
docker-compose exec auth-service env | grep DATABASE

# 应该看到：
# DATABASE_URL=postgresql://app_user:app_password_2025@postgres:5432/short_video_platform
```

**错误3：数据库未初始化**
```bash
# 运行数据库迁移
cd backend
alembic upgrade head

# 或手动创建表
docker exec -it short_video_postgres psql -U app_user -d short_video_platform -f /path/to/init.sql
```

### 3. Redis连接失败

#### 检查方法
```bash
# 检查Redis是否运行
docker ps | grep redis

# 测试Redis连接
docker exec -it short_video_redis redis-cli ping
# 应该返回：PONG
```

#### 常见错误

**错误1：Redis未启动**
```bash
# 解决方案
docker-compose up -d redis
```

**错误2：连接配置错误**
```bash
# 检查环境变量
docker-compose exec auth-service env | grep REDIS
```

### 4. 导入错误（ImportError）

#### 常见错误信息
```
ModuleNotFoundError: No module named 'common'
ImportError: cannot import name 'xxx' from 'common.models'
```

#### 解决方案

**检查1：路径配置**
```python
# 确保main.py中有正确的路径配置（所有服务都已配置）
project_root = os.path.abspath(os.path.join(os.path.dirname(__file__), '../../..'))
sys.path.append(project_root)
```

**检查2：common库结构**
```bash
# 检查common目录结构
ls -la backend/common/
ls -la backend/common/models/
ls -la backend/common/config/
ls -la backend/common/database/
ls -la backend/common/utils/
```

**检查3：Dockerfile中的COPY命令**
```dockerfile
# 确保Dockerfile复制了common目录（所有服务的Dockerfile都已配置）
COPY . .
# 这会复制整个backend目录，包括common目录
```

### 5. 端口冲突

#### 检查方法
```bash
# 查看端口占用
lsof -i :8001
lsof -i :8002
```

#### 解决方案
```bash
# 方法1：停止占用端口的进程
kill -9 <PID>

# 方法2：修改docker-compose.yml中的端口映射
# 例如：将 "8001:8001" 改为 "18001:8001"
```

### 6. 服务依赖问题

#### 检查方法
```bash
# 查看服务启动顺序
docker-compose ps

# 检查服务依赖
docker-compose config | grep depends_on
```

#### 解决方案
```bash
# 确保基础设施先启动
docker-compose up -d postgres redis zookeeper kafka

# 等待基础设施就绪
sleep 10

# 再启动应用服务
docker-compose up -d auth-service content-service
```

## 🔧 系统化排查步骤

### 步骤1：检查基础设施

```bash
# 1. 检查所有容器状态
docker-compose ps

# 2. 检查基础设施健康状态
docker-compose exec postgres pg_isready -U app_user
docker-compose exec redis redis-cli ping
docker-compose exec kafka kafka-broker-api-versions --bootstrap-server localhost:9092
```

### 步骤2：检查服务日志

```bash
# 查看所有服务日志
docker-compose logs --tail=100

# 查看特定服务日志
docker-compose logs -f auth-service
docker-compose logs -f content-service

# 查找错误
docker-compose logs | grep -i error
docker-compose logs | grep -i exception
docker-compose logs | grep -i traceback
```

### 步骤3：测试服务连接

```bash
# 测试健康检查端点
curl http://localhost:8001/health
curl http://localhost:8002/health

# 测试API端点
curl http://localhost:8001/
curl http://localhost:8002/

# 如果失败，查看详细错误
curl -v http://localhost:8001/health
```

### 步骤4：检查代码问题

```bash
# 进入容器检查
docker-compose exec auth-service bash

# 在容器内测试
python -c "from common.config.settings import settings; print(settings.DATABASE_URL)"
python -c "from common.database.connection import get_db; print('OK')"

# 检查Python路径
python -c "import sys; print('\n'.join(sys.path))"

# 检查common模块导入
python -c "from common.models import User; print('Common模块导入成功')"
```

## 🐛 常见错误及解决方案

### 错误1：`ModuleNotFoundError: No module named 'common'`

**原因**：Python路径配置错误或common目录未复制到容器

**解决**：
```bash
# 检查Dockerfile
cat services/auth/Dockerfile

# 确保有：
# COPY . .
# 或
# COPY common/ /app/common/

# 重建镜像
docker-compose build auth-service
docker-compose up -d auth-service
```

### 错误2：`sqlalchemy.exc.OperationalError: could not connect to server`

**原因**：数据库连接失败

**解决**：
```bash
# 1. 检查PostgreSQL是否运行
docker-compose ps postgres

# 2. 检查连接字符串
docker-compose exec auth-service env | grep DATABASE

# 3. 测试连接
docker-compose exec auth-service python -c "from common.database.connection import engine; engine.connect()"

# 4. 如果失败，重启PostgreSQL
docker-compose restart postgres
```

### 错误3：`AttributeError: 'NoneType' object has no attribute 'ping'`

**原因**：Redis连接失败

**解决**：
```bash
# 1. 检查Redis
docker-compose ps redis

# 2. 重启Redis
docker-compose restart redis

# 3. 检查环境变量
docker-compose exec auth-service env | grep REDIS
```

### 错误4：`ImportError: cannot import name 'router' from 'app.api.auth'`

**原因**：API文件不存在或导入路径错误

**解决**：
```bash
# 1. 检查文件是否存在
ls -la services/auth/app/api/auth.py

# 2. 检查文件内容
cat services/auth/app/api/auth.py | head -20

# 3. 检查__init__.py
ls -la services/auth/app/api/__init__.py
```

### 错误5：服务启动后立即退出

**原因**：启动时发生异常

**解决**：
```bash
# 查看退出码
docker-compose ps

# 查看完整日志
docker-compose logs auth-service

# 常见原因：
# - 数据库连接失败
# - 配置验证失败
# - 导入错误
```

## 📋 快速诊断命令

```bash
# 一键诊断脚本
cd backend

echo "=== 检查容器状态 ==="
docker-compose ps

echo "=== 检查基础设施 ==="
docker-compose exec postgres pg_isready -U app_user || echo "PostgreSQL未就绪"

echo "=== 检查服务健康 ==="
curl -s http://localhost:8001/health || echo "Auth服务未响应"
curl -s http://localhost:8002/health || echo "Content服务未响应"

echo "=== 检查最近错误 ==="
docker-compose logs --tail=20 | grep -i error
```

## 🆘 获取详细错误信息

### 方法1：查看完整日志
```bash
# 查看所有服务日志
docker-compose logs > all_logs.txt

# 查看特定服务的完整日志
docker-compose logs auth-service > auth_logs.txt
```

### 方法2：进入容器调试
```bash
# 进入服务容器
docker-compose exec auth-service bash

# 在容器内测试
python -c "import sys; sys.path.append('/app'); from common.config.settings import settings; print(settings.DATABASE_URL)"
```

### 方法3：重新构建并查看构建日志
```bash
# 重新构建服务
docker-compose build --no-cache auth-service

# 查看构建过程
docker-compose build auth-service 2>&1 | tee build.log
```

## 📞 需要帮助时提供的信息

如果问题仍未解决，请提供以下信息：

1. **服务状态**：`docker-compose ps` 的输出
2. **错误日志**：`docker-compose logs [service_name]` 的输出
3. **健康检查结果**：`curl http://localhost:8001/health` 的结果
4. **Docker版本**：`docker --version` 和 `docker-compose --version`
5. **系统信息**：操作系统版本

## ✅ 验证清单

启动成功后，应该能够：

- [ ] `docker-compose ps` 显示所有服务为 "Up"
- [ ] `curl http://localhost:8001/health` 返回 `{"status":"healthy"}`
- [ ] `curl http://localhost:8002/health` 返回 `{"status":"healthy"}`
- [ ] 可以访问 `http://localhost:8001/docs` 看到API文档
- [ ] 数据库连接正常（无连接错误日志）
- [ ] Redis连接正常（无连接错误日志）
