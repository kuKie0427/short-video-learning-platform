### BUG-004 上传 complete 接口静默失败（标志性缺陷）

| 字段 | 内容 |
|---|---|
| 标题 | 上传完成接口返回 200 但视频未落库、无业务数据 |
| 服务/模块 | Upload / complete 合并接口 |
| 严重度/优先级 | 严重 / 高 |
| 发现阶段与方法 | 接口集成测试，真实落盘断言（查库验证副作用） |
| 环境 | 课程开发环境，Docker Compose，PostgreSQL 15 |
| 复现步骤 | ① init 创建上传任务 → ② 逐片 PUT 分片 → ③ 调 complete → ④ 查响应体与数据库 |
| 预期 | 200 + video_id/status/file_url，videos 表新增记录 |
| 实际 | 200 + data=null，数据库无新记录（用户视角"上传成功"但视频消失） |
| 根因 | 控制流缩进错误导致落库分支被跳过 |
| 报告措辞 | 环境+版本+复现步骤+预期实际+根因猜测，附请求/响应报文与 SQL 查询结果截图 |
| 修复/回归 | 组员修复缩进；回归用例锁定"响应必须含 video_id/status/file_url 且落库记录一致"（tests/api/test_upload_merge.py） |
| 状态 | 已关闭 |

> 要点：为什么一般测试发现不了——只断言状态码的用例永远抓不到它；我的断言标准是"状态码+响应体+数据库最终态"三位一体。

### BUG-016 网关 nginx 上游 IP 陈旧，切分链路整体 502

| 字段 | 内容 |
|---|---|
| 标题 | split 容器重建后 `location /api/split` 持续 502，E2E 切分冒烟首跑失败 |
| 服务/模块 | Nginx 网关（gateway/nginx.conf）/ 部署配置 |
| 严重度/优先级 | 一般 / 高（阻塞切分链路与 E2E，可临时规避） |
| 发现阶段与方法 | E2E 冒烟复跑（首跑 5 过 1 失败）→ 网关日志与容器内直连比对定界 |
| 环境 | Docker Compose 全栈（7 服务 + 网关 :80 + PG14 + Redis7），macOS/Docker Desktop |
| 复现步骤 | ① 重启/重建 split 容器（IP 变更）→ ② `curl http://localhost/api/split/tasks` → ③ 对比容器内 `wget http://split_service:8004/health` |
| 预期 | 网关跟随服务实例变化转发，/api/split/* 正常 |
| 实际 | 网关日志 `connect() failed (111: Connection refused) upstream: "http://172.19.0.10:8004/..."` 持续 502；而容器内按服务名直连同刻返回 200 |
| 根因 | nginx 在配置加载时一次性解析 `upstream { server split_service:8004; }` 并缓存 IP；容器重建后 IP 变更，nginx 仍用旧地址（未配 `resolver` + 变量 proxy_pass） |
| 定位证据 | `backend/docs/manual-evidence/2026-09-09-api-evidence.txt` 末段；首跑失败现场截图与 trace |
| 规避/根治 | 已规避：`docker exec api_gateway nginx -s reload` → E2E 6/6 全绿（19.6s）。根治建议（挂起，有书面理由）：nginx.conf 改用 `resolver 127.0.0.11 valid=10s;` + `set $up http://split_service:8004; proxy_pass $up$request_uri;`，或在 compose 给 gateway 加依赖重启策略。挂起理由：属部署形态优化，不改业务行为；课设交付阶段已用运行手册固化规避动作，E2E 可重复验证 |
| 回归 | `e2e/tests/split.spec.ts` 切分全链路（失败时留 trace）+ 坑 5 记于 `e2e/README.md` |
| 状态 | 已规避（运行手册化）/ 根治项挂起 |
