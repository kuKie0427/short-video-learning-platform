# 数据库本地部署

数据库相关服务由 `docker-compose.yml` 提供。完整启动流程见[启动指南](启动指南.md)。

## 基础设施服务

`docker-compose.yml` 声明的基础设施均带健康检查，应用服务通过 `depends_on` 等待其就绪：

| 服务 | 容器名 | 端口 | 说明 |
|------|--------|------|------|
| PostgreSQL | `short_video_postgres` | 5432 | 主数据库，镜像 `postgres:14` |
| Redis | `short_video_redis` | 6379 | 缓存与 Celery broker，镜像 `redis:7-alpine`，默认无密码 |
| Zookeeper | `short_video_zookeeper` | 2181 | Kafka 依赖 |
| Kafka | `short_video_kafka` | 9092 | 消息队列 |

## 启动数据库服务

```bash
cd backend
docker-compose up -d postgres redis kafka
docker-compose ps
```

`zookeeper` 随 `kafka` 自动启动。首次启动时镜像初始化 PostgreSQL 数据库与账号。

## 连接信息

PostgreSQL：

- 地址：`localhost:5432`
- 数据库：`short_video_platform`
- 用户：`app_user`
- 密码：`app_password_2025`

Redis：

- 地址：`localhost:6379`
- 无密码

以上默认值来自 `docker-compose.yml`，与 `env.example`、`common/config/settings.py` 保持一致。

## 验证连接

```bash
docker-compose exec postgres psql -U app_user -d short_video_platform -c "SELECT 1"

# 查看已创建的表
docker-compose exec postgres psql -U app_user -d short_video_platform -c "\dt"

docker-compose exec redis redis-cli ping
```

`\dt` 应列出 14 张表。

## 表结构

应用服务启动时调用 `init_db()`（`common/database/connection.py`），通过 SQLAlchemy `create_all` 自动创建以下 14 张表，并写入一个演示用户（手机号 `13800138000`）：

| 表名 | 说明 |
|------|------|
| `users` | 用户表 |
| `videos` | 视频表 |
| `long_videos` | 长视频表 |
| `comments` | 评论表 |
| `likes` | 点赞表 |
| `favorites` | 收藏表 |
| `follows` | 关注表 |
| `courses` | 课程表 |
| `course_videos` | 课程视频关联表 |
| `learn_records` | 学习记录表 |
| `split_tasks` | 拆分任务表 |
| `split_segments` | 拆分片段表 |
| `upload_tasks` | 上传任务表 |
| `notifications` | 通知表 |

模型定义位于 `common/models/`，全部导入于 `common/models/__init__.py`。

## 常用操作

进入 PostgreSQL 命令行：

```bash
docker-compose exec postgres psql -U app_user -d short_video_platform
```

查看日志：

```bash
docker-compose logs postgres
```

执行 SQL 文件：

```bash
docker-compose exec -T postgres psql -U app_user -d short_video_platform < your_script.sql
```

备份：

```bash
docker-compose exec postgres pg_dump -U app_user short_video_platform > backup_$(date +%Y%m%d).sql
```

恢复：

```bash
docker-compose exec -T postgres psql -U app_user short_video_platform < backup_file.sql
```

重置（删除数据卷后重新初始化，`create_all` 在应用服务启动时重建表）：

```bash
docker-compose down -v
docker-compose up -d postgres redis kafka
```

## Alembic（可选）

Alembic 已配置：`alembic.ini` 指定脚本目录 `alembic/`，`alembic/env.py` 从 `common.config.settings` 读取 `DATABASE_URL`，迁移脚本位于 `alembic/versions/`（001 至 005）。应用启动时的 `create_all` 已自动建表，Alembic 仅在需要版本化变更管理时使用：

```bash
cd backend
alembic upgrade head
alembic revision --autogenerate -m "description"
```

## 文件存储

上传文件默认存本地磁盘：`services/upload/app/services/storage.py` 读取 `STORAGE_TYPE`（默认 `local`），本地基目录 `UPLOAD_BASE_DIR` 默认 `/app/data/uploads`（compose 将 `./data` 挂载为 `/app/data`）。

S3/MinIO 是可选部署形态：设置 `STORAGE_TYPE=s3` 并配置 `S3_ENDPOINT`、`S3_ACCESS_KEY`、`S3_SECRET_KEY`、`S3_BUCKET` 后切换为对象存储。`docker-compose.yml` 未内置 MinIO，使用 S3 模式需自备对象存储服务。

## 常见问题

### 端口 5432 被占用

修改 `docker-compose.yml` 中 `postgres` 的端口映射，并同步调整连接参数：

```yaml
ports:
  - "5433:5432"
```

### 连接失败

依次检查：

1. 容器状态：`docker-compose ps`
2. 日志：`docker-compose logs postgres`
3. 首次启动等待数据库就绪（镜像初始化需数秒）

本地开发模式（非 Docker 内）运行时，需在 `.env` 中配置 `DB_HOST=localhost`，见[启动指南](启动指南.md)。

### 表没有自动创建

表由应用服务启动时的 `create_all` 创建。检查任一应用服务的启动日志：

```bash
docker-compose logs auth-service | grep -i "tables created"
```

`docker-compose.yml` 已用 `depends_on: condition: service_healthy` 保证 PostgreSQL 先于应用服务就绪。

### 停止服务

```bash
docker-compose stop            # 停止，保留数据
docker-compose down            # 停止并删除容器，保留数据卷
docker-compose down -v         # 同时删除数据卷
```
